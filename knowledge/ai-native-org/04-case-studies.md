# AI-native 组织理论：案例

> 理论的价值在于指导实践。以下是AI-native SOP在一个实际项目中的落地验证。

---

## 案例：Genesis Narrative Engine

**项目代号：** Genesis-Narrative Engine
**领域：** 游戏内容生产
**核心理念：** 从剧本开始，构建完整的游戏世界

---

## 背景：游戏行业是最需要AI-native SOP的领域

游戏生产的本质是多工种、高复杂度、极度依赖协作的创意生产：

```
剧本 → 角色设计 → 美术资产 → 程序接入 → 游戏世界
```

每个环节靠人与人沟通对齐——沟通成本指数增长，产出却线性增长。

AI工具的分发没有解决这个问题，因为协作接口没有变。

**游戏行业是最需要AI-native SOP的领域，也是最检验SOP成熟度的领域。**

---

## 实践：AI-native游戏生产的完整路径

### 第一步：世界观数据库（Structured Data的建立）

**目标：** 把剧本中的所有元素变成结构化的实体

```
剧本原文
    ↓ LLM识别实体 + 校验
角色 / 场景 / 道具 / NPC / 事件 / 规则 ...（实体）
```

世界观数据库的进展：

| 子项目 | 状态 | 说明 |
|:---|:---|:---|
| LLM识别实体 | 已完成 | 识别+校验两阶段处理，结果准确 |
| LLM提取实体关系 | 已完成 | 指定实体和关系类型，提取更准确 |
| 实体名词汇总 | 60% | 初筛完成，汇总整合未开始 |
| 世界观地图 | 10% | 地理类实体用地图展示 |
| 实体详情页 | 设计中 | 场景类实体→地图形式 |

**关键洞察：** 实体Schema的定义是最重要的——它决定了后续所有Skills和Pipeline的质量。

---

### 第二步：实体管理界面（Structured Data的应用）

**目标：** 建立实体的查看和编辑能力

每个实体包含：
- **基础元数据**：名称、类型、版本、状态
- **规格描述**：完整的上下文信息
- **关联关系**：与其他实体的连接
- **交付标准**：后续工种的产出规格

世界观地图将地理类实体的空间关系可视化，让实体之间的连接一目了然。

---

### 第三步：内容创作Skills（能力的原子化）

**目标：** 把每个工种的能力封装成可复用的Skills

当前进展：

| Skill | 状态 | 说明 |
|:---|:---|:---|
| AI辅助润色 | 开发中 | 根据人物性格生成符合语境的台词 |
| 大纲解析服务 | 30% | 从大纲提取结构化信息 |
| 剧本解析服务 | 30% | 从剧本提取实体和关系 |
| 设定解析 | 规划中 | 从设定集提取实体 |

**关键洞察：** Skills的输入输出格式必须标准化——这决定了Skills能否串联成Pipeline。

---

### 第四步：多工种Pipeline（协作的编排）

**目标：** 把多个Skills连成可执行的Pipeline

当前进展：

| Pipeline | 状态 | 说明 |
|:---|:---|:---|
| 多工种视角 | 80% | 首期提供编剧类型 |
| 内容创作流程 | 规划中 | 不同工种的场景梳理 |
| 资料片版本管理 | 80% | 支持多版本的并行管理 |

**关键洞察：** Pipeline不是一次性建完的，而是随着Skills丰富而逐步演进。

---

### 第五步：AI-native SOP的验证

当实体网络、Skills库、Pipeline都成熟后，SOP的完整形式：

```
剧本 → 实体抽取Pipeline → 角色/场景/道具实体
                              ↓
                         Skills加工 → 美术规格 → 程序规格
                              ↓
                         Pipeline编排 → 游戏世界
```

AI成为执行者，人成为设计者和审核者——这才是真正的AI-native SOP。

---

## 关键经验

### 1. 实体Schema是最重要的投入

> "LLM识别实体+校验两阶段处理，可以得到更准确的结果"
> "指定要提取的实体和关系，可以得到更准确的结果"

Schema定义的质量决定了实体网络的可用性——这是AI-native SOP的地基。

### 2. Skills的输入输出格式必须标准化

内容创作页面的设计、三栏改两栏、把标签放到topbar——这些UI改动背后的本质是Skills接口的标准化。

### 3. Pipeline需要随着Skills演进

多工种视角、内容创作流程——这些是Pipeline的抽象，但具体实现需要根据Skills的成熟度逐步迭代。

---

## 外延：游戏行业的复杂度验证了框架的通用性

游戏行业是多工种、高复杂度、极度依赖协作的创意生产领域——如果AI-native SOP在游戏行业成立，它在外推到其他领域时同样适用：

- **影视制作**：剧本→分镜→拍摄→后期→成片
- **内容创作**：素材→结构化→加工→发布
- **任何多工种协作的创意行业**

**游戏行业是AI-native SOP最难攻克的领域——如果这个框架在游戏行业被验证，它就是真正通用的方法论。**
