# 05 结论：数据治理是 AI 竞争中的护城河

## 从最底层出发

```
Input + Model = Output
```

这个等式听起来像废话。但把它结构化拆解之后，一切变得清晰。

## 第一步：把 Input 拆开

LLM 的输入不是单一的"问题"，而是复合结构：

| 组成部分 | 谁负责 |
|---------|--------|
| System Prompt | Agent 模块（技术供应商） |
| Conversation History | Agent 模块（技术供应商） |
| Tool Outputs | Agent 模块（技术供应商） |
| User Query | 用户自己 |
| Retrieved Context | **企业和个人自己** |
| User-provided Artifacts | 用户自己 |

## 第二步：划定责任边界

把 Input 拆开之后，真相显现：

- **Agent 侧模块**（System Prompt、Chat History、Tool Outputs）→ 会越来越标准化，有开源社区持续迭代，有作业可抄
- **LLM 侧**（模型能力）→ 大厂负责，模型每年迭代，能力越来越强，有作业可抄
- **Retrieved Context 侧**（知识库、数据治理）→ **没有任何人能替你做**

## 第三步：为什么这件事无法外包

这不是技术问题，是归属问题。

你的剧本里的世界观结构，只有你自己知道。你的业务知识图谱，只有你自己能定义。你的个人知识库的卡片分类，只有你自己能整理。这不是大模型能替你做的——它是**你的**领域知识，归属权在你。

而大模型和开源社区每一次进步，都在给这件"自己的事"加马力。你一旦把数据治理做好，模型能力越强，你的输出质量越高。这不是被替代，而是在被放大。

### Schema 设计没有万能解

更进一步：哪怕是 Context Engineering 这套方法本身，**垂直领域的 Schema 也必须有人参与设计**。

不同领域的数据建模完全不同——游戏剧本的实体是人物、势力、技能树；客服知识库的实体是产品功能、版本、客户反馈类型；医疗档案的实体是症状、诊断、用药记录。没有一个通用的 Schema 能覆盖所有领域。

这意味着 Schema 设计本身就是**领域知识的一部分**，它需要你深度参与审核和定义。这一层也是 RAG 的根本局限所在——RAG 能解决"用时现搜"，但解决不了"用什么结构去组织知识"的问题。后者需要对领域的深刻理解，只能人来参与。

## 第四步：输入质量决定输出质量

```
输出质量 ≈ f(模型能力, 输入质量)
```

模型能力在不断提升（供应商在负责）。但输入质量——尤其是 Retrieved Context 的质量——取决于你自己。RAG 的局限在于：它解决的是"用时现搜"，但原材料的碎片化、非结构化是 RAG 本身无法解决的。

### 结构化是决定输入质量的核心

代码为什么 AI 玩得好？因为代码是天然结构化的——有类型、有接口、有模块边界、有单测质量门禁。哪怕一个代码库几十万行，AI 也能精确地"找到定义"、"追踪引用"，收集到精确的上下文，输出高质量的结果。

更重要的是：代码文件之间的 **import 链本质上就是知识图谱**。编译器验证的不只是语法，而是这张网的连通性——引用是否存在、类型是否匹配、循环依赖是否产生。这和知识库 VKY 本质上是同一件事：节点 + 连接 = 可精确导航的知识网络。

有了这张网，模型不需要通读整个代码库——它沿着 import 链精确导航，只取需要的部分，不浪费 Token。

小说、剧本、业务文档为什么不行？因为这些原材料天然是碎片化、非结构化的，没有显式的连接定义。当知识量很大的时候，没有结构化就没有"精确检索"这回事——你不知道该用什么维度去召回，模型也不知道该去哪里找。RAG 能做的只是"猜"哪些片段相关，而知识图谱是"沿着连接走"，精确、可追溯、可验证。

这就是为什么 AI 在编程领域如鱼得水，在其他领域却总是差点意思。**不是模型不行，是输入原材料质量不够高。**

## 最终结论

> **数据治理是 AI 竞争中的护城河——它是唯一一件其他人无法替你做的事，而它又把模型每一次进步的价值放大。**

在 AI 能力即将成为核心竞争力的时代，模型会越来越强，工具会越来越标准化，社区会贡献越来越多的参考实现。但回过头来看，你会发现那个一直没被解决、一直在拖后腿的，就是这一层。

其他事情都有作业可抄——模型选型、Agent 架构、Harness 设计，都可以直接抄行业最优解。但知识库的质量、数据治理的深度、结构化的程度——这些没有标准答案，只能自己动手。而且你做得越深，模型进步给你带来的杠杆越大。

未来的企业竞争，就在这一层。

## 论证链回顾

```
1. Input + Model = Output
   ↓ 把 Input 结构化拆解
2. Input 包含多个组成部分，各有不同责任方
   ↓ 显性化责任边界
3. Retrieved Context 没有任何人能替你做
   ↓ Model 和 Agent 技术在进步
4. 每次进步都在放大做好了这件事的人
   ↓
5. 数据治理 = AI 竞争中的护城河
```

---

> **核心精神：技术会标准化，但数据不会。越早动手，收益越大。**
