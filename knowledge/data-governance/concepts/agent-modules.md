# Agent 侧子模块

> 相关阅读：[[context-structure]] — 完整的输入结构拆解
> 相关阅读：[[../02-core-concepts|02-core-concepts]] — 三方责任框架

## 为什么需要拆解

从输入视角看，Agent 不是铁板一块——它是多个子模块的协作系统，每个模块都参与决定"最终给 LLM 的是什么内容"。

理解这些子模块，才能理解 Context Engineering 中"Agent 侧"和"数据治理侧"的边界在哪里。

## 五大子模块

### 1. Prompt Builder

**职责**：把用户 query 格式化成结构化的 prompt 模板。

具体做什么：
- 提取用户意图
- 选择合适的 prompt 模板
- 注入 System Prompt 和角色定义
- 组装成完整的 prompt 结构

**对输入质量的影响**：决定 LLM 看到的第一层结构是否清晰。

### 2. Context Engine

**职责**：管理上下文窗口，决定哪些历史消息该保留、该截断、该压缩。

具体做什么：
- 追踪当前上下文长度
- 执行截断策略（truncation）
- 实现上下文压缩（summarization）
- 决定信息优先级

**对输入质量的影响**：在上下文有限的情况下，决定什么信息被丢弃、什么被保留。截断策略差，核心信息会被意外抛弃。

### 3. Memory Manager

**职责**：维护短期记忆和长期记忆的分层。

具体做什么：
- 管理 conversation history（短期记忆）
- 对接外部知识库或记忆系统（长期记忆）
- 决定什么时候查知识库、什么时候用对话历史
- 实现记忆的检索和召回

**对输入质量的影响**：历史信息管理不当会导致"遗忘"和"重复"，长对话场景下这个问题尤为突出。

### 4. Retriever

**职责**：从外部知识库召回相关内容。

具体做什么：
- 实现召回策略（关键词召回、语义召回、混合召回）
- 排序和过滤召回结果
- 去重和冲突检测
- 与 Memory Manager 协作

**对输入质量的影响**：召回的内容是否精准、是否完整、是否相关，直接决定 Retrieved Context 的质量。这是 Context Engineering 的关键连接点。

### 5. Tool Integrator

**职责**：把工具执行结果拼进上下文，扩展 LLM 的能力边界。

具体做什么：
- 调用外部工具（搜索、代码执行、API 等）
- 解析工具输出
- 把结果格式化成 LLM 可理解的格式
- 处理工具调用失败的情况

**对输入质量的影响**：工具输出质量差，LLM 的推理质量也会受影响。但工具侧的优化属于技术供应商的职责。

## 边界在哪里

| 模块 | 优化方向 | 责任方 |
|------|---------|--------|
| Prompt Builder | Prompt 工程、模板设计 | 技术供应商 + 企业/个人 |
| Context Engine | 截断策略、压缩算法 | 技术供应商 |
| Memory Manager | 记忆分层、检索策略 | 技术供应商 |
| Retriever | 召回算法、排序策略 | 技术供应商 + **企业/个人（Schema）** |
| Tool Integrator | 工具生态、调用机制 | 技术供应商 |

**关键结论**：Retriever 的算法是技术供应商做的，但召回的原材料——知识库的内容结构——是企业/个人自己要治理的。

## 与 Context Engineering 的关系

Agent 侧子模块负责"**怎么组织输入**"：
- 选择哪些信息
- 以什么格式组装
- 以什么策略截断

数据治理侧负责"**输入的原材料是什么**"：
- 知识库里的实体是否完整
- Schema 设计是否合理
- 召回内容是否精准

**两者结合，才能构建完整的 Context Engineering。**
