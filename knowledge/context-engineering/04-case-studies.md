# 04 案例

## 案例一：游戏剧本知识库

### 背景

某游戏公司拥有大量剧情剧本，包含：
- 数百个可操控角色
- 数十个势力阵营
- 复杂的人物关系和故事线
- 庞大的技能、物品、世界观设定

### 痛点

用传统 RAG 做 AI 剧本创作时：
- 人物关系前后矛盾（第三章提到某个势力的设定，第五章忘了）
- 技能描述不一致（同一个技能在不同场景表现不同）
- 无法保证信息完整性（提到某个物品时，忘了它的来历）
- 每次创作都要让 AI "重新理解"这个世界

### 解决方案：LLM-Wiki 实践

**Step 1：Schema 设计**

人工设计核心实体 Schema：

```yaml
人物:
  - id: unique identifier
  - name: 姓名
  - faction: 所属势力
  - attributes:
      - 性格
      - 背景
      - 能力
  - relations:
      - type: [师徒/恋人/仇敌/...]
      - target: 关联人物
      - context: 关系上下文

地点:
  - id: unique identifier
  - name: 名称
  - controlling_faction: 控制势力
  - description: 描述
  - connections: [关联地点, ...]

技能:
  - id: unique identifier
  - name: 技能名
  - type: [攻击/防御/辅助/...]
  - user: 使用者
  - effects: 效果描述
  - cooldown: 冷却
```

**Step 2：离线抽取与审核**

用 LLM 按 Schema 批量抽取实体，人工逐条审核。

**Step 3：图数据库存储**

用图数据库存储实体和关系，支持：
- 关系路径查询（"李逍遥和剑圣之间的师徒关系链"）
- 势力影响分析（"拜月教的势力范围变化"）
- 冲突检测（"同一技能的矛盾描述"）

**Step 4：在线创作辅助**

AI 剧本创作时，根据当前场景自动组装上下文：

```
当前场景：李逍遥在蜀山派与剑圣对话

自动召回：
- 李逍遥档案（人物属性、关系网络）
- 剑圣档案
- 蜀山派设定（地点、势力、规矩）
- 相关历史事件（师徒渊源）
- 近期剧情摘要（维持连贯性）
```

### 效果

- 人物关系100%一致性
- 场景描述自动关联背景设定
- 创作时实时检索，零幻觉
- 新人加入项目，通过知识库即可了解世界观

## 案例二：个人知识库（Obsidian + LLM）

### 背景

个人研究者，需要管理大量论文、笔记、项目文档。

### 痛点

- 笔记越记越多，但"用的时候找不到"
- RAG 召回的东西是碎片，拼不成完整的理解
- 每次写东西都要"重新想"而不是"直接调"

### 解决方案

参考 LLM-Wiki 的思路：

1. **双向链接 + 卡片笔记**：Obsidian 做结构化沉淀
2. **人工定义笔记分类 Schema**：项目 / 概念 / 人物 / 方法论
3. **LLM 辅助抽取**：定期用 LLM 从新文档中抽取关键实体，补充到笔记网络
4. **按需检索**：写作时直接查知识库，不重复读原始文档

### 效果

- 笔记从"收藏"变成"可执行的资产"
- 写作时上下文完整，不用临时找资料
- 知识积累随时间增值，而不是越积越乱

## 案例三：企业知识库（客服 + 产品文档）

### 背景

某 SaaS 产品，拥有大量产品文档、客服对话记录、技术文档。

### 痛点

- 客服回答不一致，同样的问题不同的客服给了不同的答案
- 产品文档更新后，AI 不知道，还在用旧版本回答
- 跨文档的知识关联丢失（某个功能的变化历史）

### 解决方案

1. **Schema 定义**：产品功能 / 版本 / 负责人 / 客户反馈类型
2. **文档结构化**：LLM 按 Schema 抽取产品功能点、更新历史
3. **知识图谱**：维护功能-版本-负责人-客户反馈的关系网络
4. **一致性检查**：自动检测客服回答与官方文档的冲突

### 效果

- 客服回答标准化，减少矛盾
- 产品更新后 AI 知识库同步更新
- 快速追溯功能变化历史和决策原因
