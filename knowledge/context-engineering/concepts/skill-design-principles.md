# Skill 设计原则：从 CE 框架到落地实践

> **来源：** 基于 LLM Wiki 实践（Andrej Karpathy）与 OpenClaw + Obsidian 知识管理范式，结合 Context Engineering 理论框架推导而出。
>
> **核心结论：** Skills 是工具，可复制；Schema 是约束，只能自己推导。Skill 设计的目的不是给出一套拿来就用的流程，而是提供一套推导自己 Schema 的方法论。

---

## 原则 1：Schema 第一性

做任何知识管理之前，先问：
- 这个领域的核心概念是什么？
- 概念之间是什么关系？

**先把 Schema 推出来，再决定怎么入库、怎么连接。**

Schema 不是结果，是起点。没有 Schema 的知识库是堆砌，有 Schema 的知识库才是网络。

---

## 原则 2：输入即治理

问题越前置，成本越低。入库那一刻没处理好，后面每个环节都在还债。

入库时必须完成：
- 去重检测（处理过的文章要先检查是否重复）
- 概念归一化（同义词合并）
- 摘要提取（生成表层检索内容）
- 概念抽取（识别深层节点）
- Schema 字段填充

**任何一个环节的缺失，都是在给未来埋债。**

---

## 原则 3：连接是目的，结构化是手段

不要为了结构化而结构化。每一个结构化动作，都要问：

> 这个动作有没有产生新的连接？

没有连接的节点是死知识。结构化只是让连接成为可能，连接本身才是价值。

---

## 原则 4：双层结构

| 层级 | 职责 | 特征 |
|:---|:---|:---|
| **摘要层** | 快速定位 | AI 生成，用于检索和概览 |
| **概念层** | 深度理解 | 独立文档，可展开深挖 |

两者职责不同，不能混在一起。
- 表层解决"找得到"的问题
- 深层解决"看得透"的问题

---

## 原则 5：Schema 必须可演进

你现在的 Schema 是你对领域的当前认知，它会随着学习而变。

Skill 必须支持：
- Schema 的版本记录
- Schema 的升级路径
- 旧节点向新 Schema 的迁移

**把 Schema 写成死配置是一次性博弈，可演进的 Schema 才是长期投资。**

---

## 原则 6：同义词归一化是连接的前提

不同人用不同词说的是同一个概念，链接就断了。

入库时必须处理同义词归一化：
- 建立同义词表
- 自动合并指向同一概念的不同表述
- 显式标记合并逻辑

**没有归一化的知识网络，从第一天就埋了雷。**

---

## 原则 7：健康检查是维护的一部分

定期检查不是可选项，是知识库活着的基本动作：

| 检查项 | 频率 | 处理方式 |
|:---|:---|:---|
| 链接是否失效 | 定期 | 自动修复或标记 |
| 概念是否过时 | 定期 | 触发更新流程 |
| Schema 是否需要更新 | 定期 | 人机协同评估 |
| 摘要与概念层是否一致 | 定期 | 自动校准 |

---

## 原则 8：QA 沉淀是知识复利

多轮讨论里产生的洞察，是非常高质量的知识原料。

机制设计：
- 高质量讨论 → 自动归档到 QA 库
- QA 库本身 → 成为新的检索源
- 新检索结果 → 反哺概念层更新

**没有归档机制，洞察随对话消失；有了归档，讨论本身变成生产力。**

---

## 原则 9：工具会变，原则不变

Skill 设计时要分层：

```
原则层（不变）→ 规则层（可配置）→ 工具层（可替换）
```

Obsidian 可以换，OpenClaw 可以换，但这些原则不会过时。

**做 skill 设计时，让工具层可替换，原则层不变。**

---

## 原则 10：Schema 是一种承诺和约束

你定义了节点有哪些字段，就意味着：
- 某些知识会被你显性化
- 某些知识会被你忽略

这不是坏事，是必然。

重要的是：**不要把 Schema 当成全知全能的。它是你当前认知的投影，会随着认知深化而演进。**

---

## 与 CE 框架的关联

| CE 框架概念 | 在 Skill 设计中的延伸 |
|:---|:---|
| 三方责任 | Skill 负责工具层，Schema 层只有自己能做 |
| 结构化是手段，连接是目的 | 所有结构化动作必须服务于连接 |
| 知识库侧没有标准答案 | Skill 提供推导方法，不提供标准 Schema |
| 输入质量决定输出质量 | 入库即治理，问题越前置成本越低 |

---

> **Summary：** 这个 skill 的目的不是给你一套拿来就用的流程，而是帮助你推导出属于自己的 Schema。工具可以换，原则不会变。
